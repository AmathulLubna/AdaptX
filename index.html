What is real and what is simplified. Data generation, the perturbations, the detection rule, every diagnosis statistic and the NSGA-II search — non-dominated sorting, crowding distance, tournament selection, uniform crossover, bit-flip mutation, constraint-domination — are the same algorithms as the submission. The base learner here is multinomial logistic regression rather than the MLP, and the population and dataset are smaller, so a run finishes in about a second instead of 85.

Two things worth trying. Drag drift strength down toward zero and the detector stops firing. That is the do-no-harm property, not a bug: the threshold is the sampling noise of the accuracy estimate, so a drop it cannot distinguish from chance is correctly ignored. And re-run on the same seed to get identical numbers, then change the seed to watch them move.

Only one repair family runs here. The submission implements five — PatchML, feature reweighting, class reweighting, robust preprocessing and regularisation — and routes each diagnosis to its own. This page ships PatchML's search alone, so when the diagnosis points elsewhere the panel names the family the real system would use and states which one actually ran.

One scenario is missing here. The full benchmark includes class imbalance; this demo leaves it out because a fixed linear model is provably insensitive to a pure prior shift — per-class recall does not change when only the class proportions do — so it would show a failure that never arrives. The MLP in the submission does degrade under it, and it is scored there.

The loop

Detect, diagnose, treat, then check the patient recovered

The diagnosis is not decoration. It selects which repair family the evolutionary search explores, so the system never searches all five blindly. That is the operational difference between this and generic AutoML.

STAGE 1

Detect

Is the drop real, or sampling noise? The threshold is the binomial standard error of the accuracy estimate, so it adapts to sample size instead of being a tuned constant.

STAGE 2

Diagnose

An evidence vector over five causes. No classifier is trained — each cause is scored by a direct measurement of its own mechanism.

STAGE 3

Select

The leading hypothesis routes to one repair family. A runner-up shortlist provides the fallback, because a diagnosis is a belief, not a certainty.

STAGE 4

Evolve

NSGA-II over five objectives and three hard constraints. Written from scratch in NumPy — no pymoo dependency.

STAGE 5

Validate

Scored on drift levels the search never saw, then emitted as a machine-readable repair report.

Diagnosis-guided candidate pruning

We ask the failing model to predict on the new pool and compute each sample's margin — the gap between its top two class probabilities. The 192 lowest-margin rows are kept: those are the samples lying nearest the decision boundary the shift has displaced. A sample the model is confidently right about carries almost no repair signal.

This cuts the space from 21200 to 2192, and uses only the model's own outputs — no labels, no ground truth — so it is legitimate on unlabelled data at deployment time.

Replay is a correctness requirement

Every fine-tune mixes in original training samples. Without replay, adapting on a small shifted patch causes catastrophic forgetting, and a class can be absent from the batch entirely — at which point partial_fit cannot run at all.

Generation zero is seeded with prefix masks over the uncertainty ranking, so the search starts from a strong front rather than hunting for one. That is why a five-generation budget suffices.

Search

Five objectives, no weighted sum

"Best" is not one thing. A repair using 500 samples may be marginally more accurate than one using 30; which wins depends on what you can afford. So the search returns the trade-off surface, and a single deployment point is chosen from it afterwards.

Why not scalarise

A weighted sum bakes in a preference nobody chose, and it cannot reach non-convex regions of the front — no weight vector selects those points, so you would never find them. Weights are applied only when picking the final model from the finished front, never during exploration.

Constraints without penalty weights

Three hard constraints — beat the failed model by at least 0.01, stay under 1.5× the parameter count, keep the sub-population accuracy gap under 0.25 — are enforced by constraint-domination. Feasible beats infeasible; among infeasible, less violation wins. No penalty coefficient to justify.

Reproducibility

Determinism, and the three ways it breaks

An earlier build was deterministic for a single evaluation and for generation one, then diverged. That signature has exactly three causes. All three are closed by construction, not patched over.

1 — A shared global RNG stream

If evaluation draws from the same global stream as the genetic operators, any change in how many draws an evaluation makes shifts the stream for every later operator call. Generation one looks fine because nothing has perturbed the stream yet. Fixed by seeding each evaluation from a BLAKE2b hash of the genome's own contents, so equal genomes are guaranteed equal fitness.

2 — Threaded BLAS

Multi-threaded kernels split dot products across threads, so summation order depends on thread scheduling and identical inputs can produce bit-different weights. SGD amplifies that until it flips dominance comparisons between near-tied candidates. Fixed by pinning thread counts on the first line of the entrypoint, before NumPy is imported.

3 — Unstable sorts

Ties in crowding distance resolved by an unstable sort give different survivors run to run. Fixed by making every sort stable, and by keeping set and dictionary iteration order out of every decision.

The consequence

Fitness becomes a genuine mathematical function on genome space rather than a random variable, which is what lets the convergence argument hold at all. Verified two ways: a twenty-generation test that deliberately desynchronises the global RNG mid-run, and two separate processes producing byte-identical reports.

Honest accounting

What this does not do

Stated here rather than waiting to be found. A system that reports only its wins is not a diagnostic system.

  1. The benchmark is synthetic. Scenarios are generated with known causes, which is what makes diagnosis measurable — but transfer to real-world drift is unproven.
  2. Classification only. Regression and generative modelling are in the track theme and are not implemented.
  3. Overfitting recovers only 0.29. Repairing memorisation needs more than the 70 training samples that scenario has; regularisation alone cannot recover what was never learned.
  4. Input corruption is roughly neutral. Its full-retrain ceiling sits below the failed model, so the recovery metric is degenerate there and the repair neither helps nor harms.
  5. One cause per scenario. Real failures are often compound. The evidence vector supports mixtures; the benchmark does not test them.
  6. Diagnostic scales are chosen, not learned. They are set from each statistic's null distribution on unperturbed data and are monotone in perturbation strength — but they remain design choices.
